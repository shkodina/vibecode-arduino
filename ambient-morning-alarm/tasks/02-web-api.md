# Task 02: web interface and HTTP API

> **For agentic workers:** можно выполнять в отдельной сессии после или
> параллельно с `01-firmware-core.md`, если сохраняется общий контракт функций.

## Цель

Добавить веб-страницу на порту `80` и HTTP JSON API для настройки 10
будильников, обратного таймера, теста свечения, статуса устройства и остановки
активного свечения.

## Ожидаемые файлы

- Изменить: `ambient-morning-alarm/ambient-morning-alarm.ino`
- При необходимости создать: `ambient-morning-alarm/web_page.h`
- При необходимости создать: `ambient-morning-alarm/api_handlers.h`
- Не менять: Android-папку `ambient-morning-alarm--apk`

## Зависимости

Использовать функции из `01-firmware-core.md`:

```cpp
String buildStatusJson();
String buildSettingsJson();
bool applySettingsJson(const String& body, String& errorMessage);
bool startTimer();
bool startLightTest(const LightModeConfig& mode);
void stopActiveRun();
```

Если ядро ещё не готово, можно сделать временные заглушки только внутри этой
ветки работ, но итоговый PR/патч должен использовать реальные функции ядра.

## HTTP маршруты

Реализовать такие endpoint:

- `GET /` — HTML-страница настроек.
- `GET /api/settings` — все будильники и таймер.
- `POST /api/settings` — сохранить все будильники и таймер.
- `GET /api/status` — текущий статус устройства.
- `POST /api/stop` — остановить активный будильник, таймер или тест.
- `POST /api/timer/start` — запустить обратный таймер с сохранёнными
  настройками.
- `POST /api/test/start` — запустить тестовый режим свечения с параметрами из
  тела запроса.
- `POST /api/test/stop` — остановить тестовый режим.

Все ответы API должны быть JSON. При ошибке возвращать:

```json
{
  "ok": false,
  "error": "opisanie-oshibki"
}
```

При успехе возвращать:

```json
{
  "ok": true
}
```

или объект данных для `GET` endpoint.

## HTML интерфейс

Страница должна быть самостоятельной: HTML, CSS и JavaScript можно хранить в
`PROGMEM` как в соседнем `lolin-web-pulse`.

Стиль:

- тёмный фон;
- чёрно-оранжевая палитра;
- адаптация под экран телефона;
- крупные элементы управления;
- без внешних CDN и интернет-зависимостей.

Обязательные области страницы:

1. Шапка:
   - текущее время устройства;
   - статус WiFi;
   - статус NTP;
   - версия прошивки.
2. Активный запуск:
   - тип активного запуска;
   - номер будильника, если активен будильник;
   - оставшееся время;
   - кнопка `Стоп`.
3. Будильники:
   - 10 карточек;
   - включение/выключение;
   - номер `0..9`;
   - часы и минуты через `input type=\"number\"` и, если удобно, скролл;
   - выбор режима `ramp` или `pulse`;
   - параметры режима;
   - дни недели, понедельник первый, воскресенье последний.
4. Таймер:
   - часы и минуты ожидания;
   - параметры пульсации;
   - кнопка запуска.
5. Тест свечения:
   - выбор `ramp` или `pulse`;
   - параметры режима;
   - кнопки `Старт` и `Стоп`.

## JavaScript контракт

При загрузке страницы:

1. запросить `GET /api/settings`;
2. отрисовать будильники и таймер;
3. каждые 2 секунды запрашивать `GET /api/status`;
4. показывать ошибку в баннере, если запрос не удался.

При сохранении:

1. собрать форму в JSON из `../concept-plan.md`;
2. отправить `POST /api/settings`;
3. после успеха перечитать `GET /api/settings`;
4. при ошибке показать текст из поля `error`.

## Валидация

Минимальная валидация должна быть и в браузере, и на контроллере:

- часы `0..23`;
- минуты `0..59`;
- яркость `0..100`;
- `finishBrightness` не меньше `startBrightness`;
- длительности больше нуля, кроме `darkSeconds`, где допускается `0` для
  режима `ramp`;
- `weekdaysMask` не больше `127`.

## Критерии готовности

- Открытие `/` отдаёт страницу без внешних зависимостей.
- Страница показывает все 10 будильников.
- Изменение будильника сохраняется и читается обратно.
- `GET /api/status` возвращает текущее время, версию, NTP, WiFi и активный
  запуск.
- `POST /api/stop` гасит ленту через `stopActiveRun()`.
- `POST /api/test/start` позволяет подобрать параметры света без сохранения.
- API контракт совпадает с Bluetooth-контрактом из `03-bluetooth.md`.

## Проверка

```bash
cd ambient-morning-alarm
./sborka.sh
```

После заливки:

```bash
curl http://DEVICE_IP/api/status
curl http://DEVICE_IP/api/settings
curl -X POST http://DEVICE_IP/api/stop
```

Ручная проверка:

1. Открыть `http://DEVICE_IP/` с телефона.
2. Сохранить один будильник.
3. Перезагрузить плату.
4. Убедиться, что будильник остался в настройках.
5. Запустить тест `ramp`, затем остановить.
6. Запустить тест `pulse`, затем остановить.
