# lolin-web-pulse

Веб-пульсометр на Lolin NodeMCU v3 (ESP8266). Модуль читает аналоговый датчик
пульса, считает удары в минуту и отдаёт страничку, которая пульсирует красным
в темп сердца.

## Идея и цель

Хотелось получить "живой" индикатор пульса без экрана и без провода к
компьютеру: воткнул модуль в любую розетку или повербанк, открыл его адрес
с телефона или ноутбука - и видишь свой пульс.

Цель была такая:

- в левом верхнем углу страницы - число ударов в минуту, обновляется само;
- весь экран пульсирует красным в темп сердца: яркий на пике, тусклый на спаде;
- никаких кнопок и настроек, просто открыть адрес в браузере.

Небольшая задержка (пара секунд на накопление статистики) допустима: пульс
считается по среднему из последних промежутков между ударами.

## Концепт решения

Работа поделена между модулем и браузером, и это осознанное решение.

**Модуль** занимается только измерением. Он читает датчик 200 раз в секунду,
ищет удары и отдаёт по запросу три числа: текущий пульс, номер последнего
удара и сколько миллисекунд с него прошло.

**Браузер** занимается только показом. Он раз в 300 мс спрашивает у модуля
свежие числа, а саму анимацию рисует сам, 60 кадров в секунду, через
`requestAnimationFrame`.

Почему не гонять анимацию с модуля: тогда плавность зависела бы от сети и
от того, успевает ли ESP8266 отвечать. А так сеть нужна только чтобы
синхронизировать темп, и пульсация остаётся гладкой даже при задержках.
Номер удара нужен именно для этого: по нему страница понимает, что случился
новый удар, и подводит свои часы под часы модуля.

## Схема подключения

Датчик пульса - аналоговый, на 3 провода (PulseSensor / KY-039 и похожие).

```text
        Lolin NodeMCU v3                  Датчик пульса
       +-----------------+              +----------------+
       |                 |              |                |
       |  3V3       [ ]--+--------------+-- VCC (красный)|
       |                 |              |                |
       |  GND       [ ]--+--------------+-- GND (чёрный) |
       |                 |              |                |
       |  A0        [ ]--+--------------+-- Signal       |
       |                 |              |                |
       |  USB micro      |              +----------------+
       +--------+--------+
                |
             питание
```

Три важных момента:

1. Сигнал идёт ТОЛЬКО на `A0`. У ESP8266 всего один аналоговый вход, и это он.
   На цифровые ножки (`D1`, `D5`, `D8` и прочие) такой датчик вешать нельзя:
   они видят только 0 и 1, а нам нужна плавная волна кровотока.
2. Особенно нельзя на `D8`. Это `GPIO15`, он участвует в выборе режима
   загрузки, и при высоком уровне на нём плата просто не загрузится.
3. Питание берём с `3V3`. У входа `A0` на плате NodeMCU стоит делитель,
   поэтому 3.3 В он терпит. Если питать датчик от 5 В (`VIN`/`VU`), его выход
   может выйти за 3.3 В и повредить вход.

## Как это измеряет пульс

Полезный сигнал слабый: размах пульсовой волны около 25-30 единиц АЦП при
том, что одна единица это ~3.2 мВ. Поверх него сидит медленный дрейф от
дыхания и прижима пальца, а движение руки даёт выбросы в 10 раз сильнее
самого пульса. Поэтому обработка идёт в несколько шагов:

1. **Сглаживание** - убираем шум АЦП, постоянная времени ~100 мс.
   Ставили 40 мс - оказалось мало: сигнал шёл вплотную к шуму, детектор ловил
   шум и упирался в защитный минимум 350 мс, показывая около 160 уд/мин.
2. **Базовая линия** - считаем медленный уровень сигнала (~1.5 с) и вычитаем
   его. Пульсовая волна начинает колебаться вокруг нуля, дрейф больше не мешает.
3. **Сила волны** - считаем среднеквадратичное значение (~3 с). Именно
   среднеквадратичное, а НЕ максимум: максимум запоминает случайный выброс от
   движения и надолго задирает порог, из-за чего настоящие удары пропускаются.
4. **Порог** - 0.9 от силы волны. Удар это переход волны снизу вверх через
   порог. Чтобы поймать следующий, волна должна сначала опуститься до 0.3 силы
   (защита от дребезга).
5. **Проверка промежутка снизу** - если промежуток короче 55% от среднего, это
   вторичный пик пульсовой волны (дикротический зубец), а не новый удар.
   Без этой проверки пульс показывался ровно вдвое больше настоящего.
6. **Проверка промежутка сверху** - если промежуток длиннее 160% от среднего,
   значит один удар мы пропустили и промежуток двойной. Удар считаем (иначе
   анимация рассинхронизируется), но в усреднение не берём. Без этой проверки
   один пропуск ронял цифру с 100 до 83.
7. **Усреднение** - пульс считается по среднему из 5 последних промежутков.

Если сила волны меньше 1.0 - считаем, что пальца нет, и показываем прочерк.

## Установка инструментов

Нужен `arduino-cli` и ядро ESP8266. Библиотеки ставить отдельно НЕ надо:
`ESP8266WiFi` и `ESP8266WebServer` входят в состав ядра.

```bash
# сам arduino-cli
curl -fsSL https://raw.githubusercontent.com/arduino/arduino-cli/master/install.sh | sh
sudo mv bin/arduino-cli /usr/local/bin/

# конфиг
arduino-cli config init

# URL с описанием плат ESP8266 (без него ядро не найдётся)
arduino-cli config add board_manager.additional_urls \
  https://arduino.esp8266.com/stable/package_esp8266com_index.json

# обновить индекс и поставить ядро
arduino-cli core update-index
arduino-cli core install esp8266:esp8266

# проверить
arduino-cli core list
```

## Пароль от wifi

Пароля в коде нет и быть не должно: скетч в git, а пароль от домашней сети
в git попадать не может. Имя сети и пароль приходят снаружи, на этапе сборки,
через определения компилятора `WIFI_SSID` и `WIFI_PASS`.

Если их не передать, сборка упадёт с понятной ошибкой:

```text
error: #error "WIFI_SSID ne zadan. Sobiray cherez ./sborka.sh, smotri readme.md"
```

Сделано именно ошибкой, а не предупреждением, специально: `arduino-cli`
по умолчанию скрывает предупреждения компилятора, поэтому обычный `#warning`
остался бы незамеченным - и в плату уехала бы прошивка с пустым паролем.

### Способ 1: скрипт сборки (так удобнее)

Один раз завести себе файл настроек:

```bash
cp .env.primer .env
nano .env          # вписать имя сети, пароль, порт и режим
```

Дальше собирать и заливать так:

```bash
./sborka.sh           # только собрать
./sborka.sh zalit     # собрать и залить в плату
```

Скрипт сам подставит настройки в компилятор и проверит, что всё заполнено.
Файл `.env` прописан в `.gitignore`, в репозиторий он не уедет.

### Способ 2: руками через переменные окружения

Если скрипт не нужен, можно передать всё напрямую. Экранирование кавычек
обязательно: в коде это строки, а не числа.

```bash
export WIFI_SSID="MoyaSet"
export WIFI_PASS="moy-parol"

arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 \
  --build-property "compiler.cpp.extra_flags=-DWIFI_SSID=\"$WIFI_SSID\" -DWIFI_PASS=\"$WIFI_PASS\"" \
  .
```

Тот же флаг `--build-property` нужен и при `upload`, если заливать без
предварительной сборки.

Проверить, что пароль реально попал в прошивку, можно так:

```bash
arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 \
  --build-property "compiler.cpp.extra_flags=-DWIFI_SSID=\"$WIFI_SSID\" -DWIFI_PASS=\"$WIFI_PASS\"" \
  --output-dir /tmp/proverka .

strings /tmp/proverka/*.bin | grep "$WIFI_PASS"
```

Честное предупреждение: этот способ **не** прячет пароль от того, у кого
на руках сама плата. Пароль лежит в прошивке открытым текстом, и его видно
командой `strings` выше. Задача тут другая - не пустить пароль в git.
Настоящее сокрытие потребовало бы хранить пароль вне прошивки, например
вводить его через страницу настройки при первом включении.

## Сборка и заливка

Плата Lolin NodeMCU v3 это `esp8266:esp8266:nodemcuv2` (NodeMCU 1.0, ESP-12E).
Отдельного профиля под "v3" нет и не нужно: отличается только разводка пары
пинов питания, прошивка та же.

Проще всего через скрипт (он сам подставит пароль из `.env`):

```bash
cd /home/blobby/home_cnf/xtmp-work-dir/vibecode-arduino/lolin-web-pulse
./sborka.sh zalit
```

То же самое руками, если хочется видеть все шаги:

```bash
export WIFI_SSID="MoyaSet"
export WIFI_PASS="moy-parol"
NASTROYKI="compiler.cpp.extra_flags=-DWIFI_SSID=\"$WIFI_SSID\" -DWIFI_PASS=\"$WIFI_PASS\""

# собрать
arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 --build-property "$NASTROYKI" .

# залить (порт подставить свой)
arduino-cli upload -p /dev/ttyUSB0 --fqbn esp8266:esp8266:nodemcuv2 .
```

Узнать порт:

```bash
arduino-cli board list
```

### Если работаем из WSL

На этой машине WSL не смог открыть COM-порт, поэтому собираем и заливаем
через Windows-овый `arduino-cli` (он лежит внутри Arduino IDE), вызывая его
из WSL. Подробности и диагностика - в `READ-ME-NOTES/arduino/wsl.md`.

Скрипт это умеет сам, надо только поставить в `.env`:

```ini
REZHIM=wsl
PORT=COM4
```

Дальше как обычно:

```bash
./sborka.sh zalit
```

Скрипт скопирует скетч на диск C (с сетевыми путями виндовые программы
работают плохо) и вызовет виндовый `arduino-cli.exe`.

То же самое руками:

```bash
CLI="/mnt/c/Program Files/Arduino IDE/resources/app/lib/backend/resources/arduino-cli.exe"
NASTROYKI="compiler.cpp.extra_flags=-DWIFI_SSID=\"$WIFI_SSID\" -DWIFI_PASS=\"$WIFI_PASS\""

mkdir -p /mnt/c/Users/blobby/arduino-wsl/lolin-web-pulse
cp lolin-web-pulse.ino /mnt/c/Users/blobby/arduino-wsl/lolin-web-pulse/

cd /mnt/c
"$CLI" compile --fqbn esp8266:esp8266:nodemcuv2 --build-property "$NASTROYKI" \
  'C:\Users\blobby\arduino-wsl\lolin-web-pulse'
"$CLI" upload -p COM4 --fqbn esp8266:esp8266:nodemcuv2 \
  'C:\Users\blobby\arduino-wsl\lolin-web-pulse'
```

## Как смотреть консоль ком-порта

Скорость - **115200**. При старте модуль печатает адрес, который выдал роутер:

```text
Podklyuchayus k wifi: ObiVanKiNobi
.....
Wifi podklyuchen.
IP-adres modulya: 192.168.88.26
Otkroy etot adres v brauzere.
Veb-server zapushen na portu 80.
```

Сообщения написаны латиницей специально: кириллица в мониторах ком-порта
часто выводится кракозябрами.

Способы посмотреть:

```bash
# штатный монитор arduino-cli
arduino-cli monitor -p /dev/ttyUSB0 -c baudrate=115200
```

Из WSL, когда порт виден только Windows, удобно питоном (нужен `pyserial`):

```bash
cd /mnt/c && powershell.exe -NoProfile -Command "C:\Python314\python.exe C:\Users\blobby\arduino-wsl\read_serial.py"
```

Либо просто PuTTY в Windows: Connection type - Serial, Serial line - `COM4`,
Speed - `115200`.

Важно: пока монитор ком-порта открыт, он ДЕРЖИТ порт, и залить прошивку в
это время не получится. Перед заливкой монитор надо закрыть.

## Что открывать в браузере

Адрес из консоли, например `http://192.168.88.26/`. Дальше приложить палец
к датчику - через 2-3 секунды появится число.

Адрес выдаётся роутером по DHCP и после перезагрузки может измениться.
Если нужен постоянный - закрепить в роутере по MAC либо прописать статику
в скетче через `WiFi.config()`.

## Отладочные адреса

Пригодятся, если пульс ловится плохо.

| Адрес      | Что отдаёт |
|------------|------------|
| `/`        | сама страничка |
| `/dannye`  | json с пульсом, номером удара и полем `sila` (сила волны) |
| `/signal`  | запись очищенного сигнала за 40 секунд, значения умножены на 100 |

Ориентиры по силе волны (замерено на этой сборке): пальца нет - меньше 0.5,
палец лежит спокойно - 4-7, рывок или смещение пальца - десятки и сотни.

Если сила держится около 1-2, а пульс скачет - контакт с датчиком плохой.
Прижим должен быть плотным, но без давления: слишком сильное пережимает
кровоток и волна пропадает.

По записи с `/signal` можно проверить, есть ли вообще пульсовая волна:
скачать её и посчитать автокорреляцию. Пик на задержке 0.6-0.8 с как раз
соответствует пульсу 75-100 уд/мин.

## Что можно подкрутить

Все настройки собраны константами в начале скетча.

| Константа | Смысл |
|-----------|-------|
| `ALFA_BYSTROGO` | сглаживание. Меньше - тише шум, но волна размазывается |
| `SKOLKO_PROMEZHUTKOV_USREDNYAT` | больше - цифра спокойнее, но реагирует медленнее |
| `MIN_SILA` | порог "палец лежит". Ниже - чувствительнее, но больше ложных срабатываний |
| `POROG_V_SILAH` | чувствительность детектора удров |
| `MIN_DOLYA_OT_SREDNEGO` | защита от двойного счёта (вторичный пик волны) |
| `MAX_DOLYA_OT_SREDNEGO` | защита от занижения цифры при пропущенном ударе |
