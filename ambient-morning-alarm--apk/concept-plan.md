# ambient-morning-alarm--apk concept plan

Android-приложение нужно для личной настройки светового будильника
`ambient-morning-alarm` с телефона Redmi Note 12. Приложение подключается к
ESP32-C3 по BLE, показывает состояние устройства и даёт тот же функционал, что
веб-интерфейс: будильники, таймер, тест свечения и остановку активного запуска.

Этот документ можно отдавать Android-агенту вместе с task-файлами из `tasks/`.

## Границы приложения

Приложение делает:

- поиск BLE-устройства `piper-light-alarm-0000001`;
- подключение к BLE service из `../ambient-morning-alarm/tasks/03-bluetooth.md`;
- чтение статуса;
- чтение и сохранение настроек, включая WiFi SSID/пароль в NVS устройства;
- остановку активного будильника, таймера или теста;
- запуск таймера;
- запуск и остановку теста свечения;
- сборку APK через Docker.

Приложение не делает:

- облачную авторизацию;
- push-уведомления;
- фоновые службы;
- геолокацию;
- управление через интернет вне локального BLE-соединения.

## Первый экран

При запуске приложение пытается подключиться к будильнику.

Если есть активный будильник или таймер:

- показать текущее время устройства;
- показать тип активного запуска;
- показать номер будильника, если это будильник;
- показать оставшееся время;
- показать кнопку `Остановить`.

Если подключения нет или активного запуска нет:

- открыть экран настроек будильников;
- при ошибке подключения показать баннер сверху;
- баннер не должен блокировать ручное редактирование формы.

## Экраны

Минимальная навигация:

1. `Будильники`
   - 10 карточек будильников;
   - включение/выключение;
   - время;
   - режим `ramp` или `pulse`;
   - параметры режима;
   - дни недели.
2. `Таймер`
   - часы и минуты ожидания;
   - параметры пульсации;
   - кнопка запуска таймера.
3. `Тест`
   - выбор режима;
   - параметры режима;
   - кнопки `Старт` и `Стоп`.
4. `Статус`
   - текущее время;
   - версия прошивки;
   - NTP;
   - WiFi;
   - активный запуск.

Можно реализовать `Статус` как верхнюю панель над тремя основными экранами,
если так проще.

## Разрешения Android

Запрашивать только права, необходимые для Bluetooth:

- Android 12+:
  - `BLUETOOTH_SCAN`;
  - `BLUETOOTH_CONNECT`.
- Android до 12:
  - `BLUETOOTH`;
  - `BLUETOOTH_ADMIN`.

`ACCESS_FINE_LOCATION` не запрашивать для Android 12+. Если выбранная
минимальная версия SDK требует location для BLE scan на старых Android,
ограничить это условием по версии SDK и описать в README.

## BLE контракт

Использовать UUID из прошивки:

```text
service UUID:        7c1b0000-7df0-4b6f-bc6f-a110c0000001
command UUID:        7c1b0001-7df0-4b6f-bc6f-a110c0000001
response UUID:       7c1b0002-7df0-4b6f-bc6f-a110c0000001
status notify UUID:  7c1b0003-7df0-4b6f-bc6f-a110c0000001
```

Команды:

- `getSettings`;
- `setSettings`;
- `getStatus`;
- `stop`;
- `startTimer`;
- `startTest`;
- `stopTest`.

Форматы JSON описаны в `../ambient-morning-alarm/tasks/03-bluetooth.md`.
Приложение не должно придумывать отдельные поля.

## Технологический выбор

Выбранный стек:

- React Native через Expo Dev Client (SDK 57);
- `react-native-ble-plx` для BLE;
- TypeScript;
- `expo prebuild` генерирует Android-проект внутри Docker перед Gradle release.

Имя устройства ищется по префиксу `piper-light-alarm-` (версия прошивки в
суффиксе может меняться). WiFi вынесен на отдельную вкладку через
`getWifi` / `setWifi`.

Главный критерий: APK должен собираться в Docker на Ubuntu 22.04 и
устанавливаться на Redmi Note 12.

## Модель данных

Приложение должно держать модели, совпадающие с JSON прошивки:

- `AlarmConfig`;
- `TimerConfig`;
- `LightModeConfig`;
- `DeviceStatus`;
- `ActiveRun`.

Сохранение настроек отправляет весь объект настроек целиком. Это проще, чем
патч-команды по одному полю, и совпадает с веб-интерфейсом.

## Обработка ошибок

- Нет Bluetooth разрешения: показать экран/баннер с кнопкой запроса разрешения.
- Устройство не найдено: показать баннер и кнопку повторного поиска.
- Подключение потеряно: оставить текущую форму на экране, показать баннер,
  не терять несохранённые изменения.
- Команда вернула `ok=false`: показать текст ошибки.
- Ответ не разобрался как JSON: показать `Ошибка протокола`.

## Docker-сборка

Сборка APK должна быть воспроизводимой:

1. Dockerfile ставит JDK, Android command line tools, SDK и Gradle.
2. Скрипт запускает контейнер в фоне или sleep-режиме.
3. Скрипт выполняет сборку внутри контейнера.
4. Скрипт копирует готовый `.apk` из контейнера в папку проекта.
5. Ключ подписи генерируется внутри Docker или стабильно хранится в volume,
   чтобы обновления приложения ставились поверх старых сборок.

Подробности в `tasks/02-docker-build.md`.

## Порядок делегирования

1. Сначала зафиксировать BLE UUID и JSON-команды в прошивке.
2. Затем реализовать Android-приложение по `tasks/01-android-app.md`.
3. Затем реализовать Docker-сборку по `tasks/02-docker-build.md`.
4. После первой сборки проверить APK на телефоне.
